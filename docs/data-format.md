# 工程数据格式

本页的类别、尺寸与坐标均为虚构的格式示例，不来自真实业务标注。软件面向图片缺陷的矩形/多边形标注及YOLO数据整理，正式标注JSON与工程管理文件分别保存。

## 基本文件

| 文件 | 内容 |
| --- | --- |
| `images/` | 工程原图 |
| `jsons/<图片主名>.json` | 对应正式标注 |
| `label.txt` | 每行一个缺陷类别 |
| `datafile.dat` | pickle 序列化的相对图片路径列表 |
| `flagfile.dat` | 与图片清单同序的整数状态列表 |
| `sample_tree.json` | 子样本分类与归类 |
| `ai_workbench/` | 项目上下文、资源、对话、产物与人工记录 |

工程清单采用历史 pickle 格式，请只打开可信来源的工程。通用交换优先使用图片、JSON 或 YOLO 数据集。

## JSON 标注

坐标以原图宽高归一化到0～1。矩形有左上和右下两个点；多边形有至少三个顶点。

```json
{
  "image_width": 960,
  "image_height": 640,
  "annotations": [
    {
      "type": "rect",
      "lable": "scratch",
      "points": [{"x": 0.2, "y": 0.3}, {"x": 0.6, "y": 0.4}]
    }
  ]
}
```

历史字段名为 `lable`，此拼写是兼容格式的一部分。导入服务兼容部分历史 `label`、`category` 字段，统一转换为内部格式；不要全局替换字段名。

图片 `sample.png` 的正式标注文件为 `jsons/sample.json`；不同目录中同主名图片可能产生冲突，需要避免混用。JSON导入只面向上述 `annotations` 结构，并接受 `rect` 和 `polygon`；不能直接当成通用LabelMe或COCO导入器。

内部保存归一化坐标。导入时，超出0～1的有效像素坐标可依据所提供的正数宽高转换；仍越界或缺少必要尺寸的坐标会报错。请先转换其他软件的字段和坐标约定，再导入。

## 状态

| 数值 | 状态 | 导出含义 |
| --- | --- | --- |
| 0 | 未标注 | 不自动当成已确认负样本 |
| 1 | 坏品 | 依据正式标注导出 |
| 2 | 完全良品 | 选择加入时，空TXT负样本 |
| 3 | 过杀品 | 选择加入时，空TXT负样本 |

设为2/3会清除该图片已有缺陷标注与子样本归类。子样本分类用于管理，不能当成额外训练类别。

## YOLO 导入导出

YOLO 检测标签为 `class x_center y_center width height`，分割标签为 `class x1 y1 x2 y2 ...`；坐标均归一化。`data.yaml` 声明类别和数据位置。

导入时，有效非空TXT为坏品，空TXT为良品，缺失TXT为未标注。相同主名冲突会跳过，外部子样本分类暂不导入。

默认输出包含 `images/train|val`、`labels/train|val`、`data.yaml` 和类别/子分类统计。AI 数据集保存在 `dataset_AI_日期_批次/`，其他内容导出在 `exports/` 下分用途目录。

## 预测与正式标注

AI 候选批次保存模型身份、实际参数、逐图预测和推理时原标注参考。预测可以单独导出JSON或带框图片；没有核对采用的预测不能直接导出成正式训练标注。

同名权重通过模型内容指纹区分，历史批次保留当时身份。人工问题记录绑定图片和对应结果；来源被删除或变化时可能失效。
