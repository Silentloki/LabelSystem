# AI 助手

## 配置

1. 打开工程，点击顶部“AI 助手”。
2. 打开“设置”，填写 API Key、完整接口地址和模型名称。
3. 默认地址为 `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions`，默认模型名为 `qwen3-vl-plus`；可用性、图像支持和费用以服务商为准。
4. 其他兼容服务需要验证相同 JSON 回复约定和图像输入。仅文本模型不能完成看图任务。

请求次数上限控制单条消息中模型与工具的循环次数；超过预算可能只完成部分工作。API Key 保存在当前窗口内存，关闭后需要重新填写。

## 对话里能做什么

| 请求 | 行为 |
| --- | --- |
| “筛出有划痕的图片” | 根据已有标注筛选分组 |
| “把这些图切成1280，再导出数据集” | 组合切图与导出；同步相交标注 |
| “把脏污改为破损” | 准备正式类别修改，预览后确认 |
| “把这张改为良品” | 准备清除缺陷标注/归类并改状态，确认后执行 |
| “记录这些图漏检” | 按你的明确判断写人工问题记录 |
| “加入问题样本集” | 保存图片及来源的引用集合，不复制或删除原图 |
| “分析这些照片” | 附送所选原图及相关结果，逐图分析 |
| “分析这个模型的推理结果” | 定位已保存候选批次，读取统计并按需看图 |
| “分析训练目录” | 读取指标、配置和统计图，给出解释与实验建议 |

项目资源在多个对话间共享，软件会自动提供项目摘要，必要时 AI 查询详情。没有记录的来源或关系保持未知。资源丢失、批次失效或选择范围不匹配时应提示核对。

## 选择范围

发送消息时固定当前选择对象。明确的“这张 / 这些”作用于选中照片；无多选时界面会提示当前单张来源。空范围不会悄悄换成整个工程。

每批看图最多10张源照片，每张可能附原图、预测叠加和局部图。更多选中照片依次翻页，在预算内汇总实际查看范围。准备图片不等于分析完成，未看清或未查看应如实显示。

切图与原图是不同对象。修改派生图状态不直接作用于原图；需要处理来源时，明确说“找到这些切图对应的工程原图，再处理”。

## 修改、人工判断与恢复

“改成良品”会修改正式状态；“记录预测正常”保存你的问题判断。AI 怀疑有误检/漏检不能自行写成人工确认。

正式修改先预览后确认，保存恢复记录。文件、图片清单或标注发生后续变化时，恢复会拒绝覆盖，避免丢失新编辑。确认不等于所有后续工具都自动获得修改授权，后续正式修改仍需相应预览。

## 数据发送与费用

配置的服务会收到近期对话、项目摘要、工具结果以及当前分析所需的图片/训练统计图。使用本地 `.pt` 模型的预测与外部视觉 AI 分析是两个独立步骤。

基础标注不需要 API Key。服务费用按实际请求计算，选图较多或组合步骤较长时可能产生多次请求。项目内保存对话、产物和请求证据；分享工程前检查其中的业务信息。

调试上下文默认隐藏，开发者可在启动前设置 `LABELSYSTEM_CONTEXT_DEBUG=1`。分享调试文件仍应核对图片、路径和备注是否适合公开。

## 当前限制

AI 不精确修改标注几何或 Mask，不自动启动训练，不提供任意 Shell/源码修改。参数建议和选错模型检查尚未完善；模型判断与建议需要实际验证。普通推理页未保存的历史预测不能凭空补造。
